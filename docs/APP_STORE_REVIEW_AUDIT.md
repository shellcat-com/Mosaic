## Submission blockers — complete in this order

1. **Deploy the corrected public pages.** Publish `site/privacy/`, `site/terms/`, and `site/account-deletion/`; then confirm every URL shows the current Sign in with Apple, RevenueCat, Event Pass, purchase-history, and subscription-cancellation language.
2. **Deploy and test account deletion.** Deploy `supabase/functions/delete-account`, configure its server-only RevenueCat secret, and verify that deleting a production test account removes Supabase Auth and RevenueCat customer data. Deletion does not cancel an Apple subscription, so test the in-app warning and Manage Subscriptions path.
3. **Finish Apple commerce setup.** Accept the Paid Apps agreement and complete tax/banking. Create `organizer_monthly`, `organizer_annual`, and `mosaic_event_pass_v2`; add pricing, localizations, review screenshots, and the subscription group; attach them to version 1.0. Mirror the products in RevenueCat's offering/entitlement configuration.
4. **Run genuine purchase tests.** With sandbox/Test Store accounts, record evidence for monthly and annual purchase, Event Pass purchase/consumption semantics, restore, cancellation, pending/Ask to Buy, expiration/grace behavior, relaunch, and server entitlement reconciliation.
5. **Publish privacy answers.** Match App Store Connect to the target manifest: Name, Email Address, User ID, Photos/Videos, Other User Content, and Purchase History; no tracking. Generate Organizer's Privacy Report and reconcile SDK declarations before publishing.
6. **Complete compliance forms.** Finish export compliance for AES-GCM/Swift Crypto, the current age-rating questionnaire, content-rights answers, and DSA/trader status where applicable.
7. **Prepare review access.** Seed stable production events in active and revealed states, replace both invitation placeholders, and fill all review-contact fields. Ensure reports are operationally monitored with a documented moderation response process.
8. **Produce the release candidate.** Free at least several GB of disk, increment build number if build 1 is unavailable, run all unit/UI tests, archive with the iOS 26 SDK and App Store distribution signing, inspect the privacy report, validate/export, upload, and select the processed build.
9. **Validate App Store Connect.** After authenticating `asc`, run strict validation, resolve every ERROR/WARNING, recheck every public URL, and only then submit for review.

Suggested validation command after credentials and the app ID are available:

```sh
asc validate --app APP_ID --version 1.0 --platform IOS --strict --output table
```
